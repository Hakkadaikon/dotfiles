# 作業の進め方

工程は superpowers、検証とgit運用の差し込みは hymme(セッション開始時に注入される using-hymme の地図)に従う。ここには両者に無い個人方針だけを置く。

## コミット

- git 管理下の変更は作業完了時に未コミットで残さず、`hymme:commit-flow` で粒度を決め `hymme:micro-commit` でコミットする。ユーザーが単一コミットを明示したときは従う。

## 自律修正

- バグ報告を受けたら、手取り足取りを求めず自分で直す。ログ、エラー、失敗テストを手がかりにする。
- CI の失敗は指示を待たずに直す。user の context switch を最小にする。

## 提出前

- 自分の成果物を一度疑う。熟練エンジニアがこれを承認するかを自問する。
